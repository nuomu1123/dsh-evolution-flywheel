# 异构批评者（Critic）

> **这是一套模板，不是标准答案。**
>
> 本模块提供的只是「一个可以粗略复用的骨架」：一次确定性的路由、一次不阻断主流程的异步批评、
> 一份可替换的提示词。它**不声称**任何模型、任何阈值、任何路由是"正确"的。
>
> 如果你的机器能部署其他家族的大模型（32B、其他厂商、云端 API），**请直接替换路由**——
> 那才是它应该有的样子。
>
> 模板本身也是动态的：提示词、严重度阈值、触发条件都应该随使用数据调整。
> **改变才是常态，寂静只是暂时的。**

## 它是什么，不是什么

| 是 | 不是 |
|---|---|
| 第二双眼睛，供审阅者参考 | 最终裁决者 |
| 异构信号的补充（不同家族 → 不同盲点） | 更聪明的同族模型（同族只会同意自己） |
| 只做结构性检查（契约/边界/矛盾/过度概括） | 判断"逻辑正确但世界不认" |

能抓到的：契约不一致、明显语法/类型错误、未处理的边界、前后矛盾、数字不一致、把单次经验写成普适规律。

抓不到的：解法在真实世界里能否用、观点对错、价值判断——这些只能靠真实世界反馈与人类否决。

## 默认路由（只是「本机现在能跑什么」）

| kind | 默认模型 | 用途 |
|---|---|---|
| `code` | `qwen2.5-coder:14b` | 代码/契约/边界检查 |
| `text` | `qwen2.5:14b` | 文本自洽、结论是否超出证据 |
| `memory` | `qwen2.5:14b` | 记忆是否可验证、是否可能过时 |
| `distill` | `qwen2.5:14b` | 提炼是否过度概括、是否缺反例 |

**换模型 = 改环境变量**，不需要改代码：

```powershell
# 换成其他家族 / 更大的模型
$env:DSH_MEMORY_CRITIC_CODE_MODEL   = "my-other-family:32b"
$env:DSH_MEMORY_CRITIC_TEXT_MODEL   = "my-other-family:32b"
$env:DSH_MEMORY_CRITIC_MEMORY_MODEL = "qwen2.5:14b"
$env:DSH_MEMORY_CRITIC_DISTILL_MODEL= "qwen2.5:14b"

# 端点（Ollama 兼容；换 vLLM / LM Studio / 云端兼容层同样填这里）
$env:DSH_MEMORY_CRITIC_URL = "http://127.0.0.1:11434"

# 打开审阅时的自动批评（默认关闭：批评会带来延迟）
$env:DSH_MEMORY_CRITIC = "on"
```

> 如果批评者服务的不是 `/api/chat` 协议，改 `src/memory/critic.ts` 里的请求构造即可——
> 这正是"模板"的含义：**协议、模型、提示词都是可替换的零件。**

## 手动触发（调试与校准）

```powershell
# 需要带上 DSH 的 Web 认证 cookie（与其它 /memory-explorer 接口相同）
curl -X POST http://127.0.0.1:3099/memory-explorer/api/critic `
  -H "content-type: application/json" `
  -d '{"kind":"code","content":"function f(){ return 1 } // 注释说返回字符串","question":"契约是否一致？"}'
```

返回：

```json
{
  "ok": true,
  "enabled": true,
  "routes": { "code": "qwen2.5-coder:14b", "text": "qwen2.5:14b", "memory": "qwen2.5:14b", "distill": "qwen2.5:14b" },
  "result": {
    "ok": true,
    "critic": "qwen2.5-coder:14b",
    "issues": [{ "severity": "high", "where": "f()", "why": "注释声明返回字符串，实际返回数字" }]
  }
}
```

## 自动触发条件（省钱省延迟）

审阅时**只在这三类条目上**调用批评者：

1. 人类干预过（`humanInterventions >= 1`）；
2. 重复出现过（`count >= 2`）；
3. 解法很长（`resolution` 超过 400 字，细节多、更容易有契约问题）。

其余条目跳过。批评意见会作为「参考意见」塞进母 Agent 的输入，母 Agent 有否决权。

## 降级语义

批评**永远不阻断主流程**：

| 情况 | 行为 |
|---|---|
| 端点不可达 / 超时（默认 25s） | `ok:false` + `degraded`，审阅继续 |
| HTTP 非 2xx | `ok:false` + `degraded: "HTTP 5xx"` |
| 输出不是 JSON | `ok:false` + `degraded: "输出无法解析为 JSON"` |
| 有意见 | `ok:true` + `issues`，按严重度排序进入提示词 |

所有调用都会写一条审计事件 `memory.critic`（只记模型名、条数、是否降级，不记正文）。

## 怎么判断这个批评者值不值得信

不要相信默认路由，用数据判断：

1. 查审计日志里的 `memory.critic` 事件，统计「提出意见的条数」与「降级次数」；
2. 结合审阅结论统计「批评被采纳的比例」（批评意见与最终 `decision` 是否一致）；
3. 三个月后你会得到类似「该模型在代码类采纳率 68%、在语义类 21%」的分布——再据此调整路由与提示词。

**没有记账的批评者只会变成噪音来源。**

## 为什么不让模型自己挑批评者

如果被批评者可以决定"由谁来批评我"，它一定会漂向"容易通过的批评者"，而且理由看起来会很合理。

所以路由是**确定性策略**：按 `kind` + 触发条件固定分配。模型只能看到批评结果，不能决定谁来说话。

## 已知局限

- 14B 级别模型的批评有噪声，假阳性可能比真问题多——所以它只做"提意见"，不做裁决；
- 它看不到真实世界，只能看到你给它的文本；
- 同族模型互相批评的价值远低于跨家族；
- 这里的一切（默认模型、提示词、阈值）都会过时，**改动的时候不要犹豫**。
